# 教学楼四楼导览与示意导航

纯静态网站，直接由 GitHub Pages 托管。保留原楼层图、31 个可点击标记、搜索、手机定位读数和手动位置箭头。

## 使用

1. 搜索教室编号，或点击图上的房间、楼梯标记。
2. 点击“开始导航到这里”。若尚未标记室内位置，先点地图上自己所在的位置。
3. 查看蓝色示意路线；用“看起点”“看终点”切换视野，或点“结束”。
4. 移动到别处后，可在“我的位置”里重新标记起点，路线会重新计算。

页面加载完成后会自动请求浏览器定位权限。允许后，设备经纬度、估计精度、最后更新时间持续显示在“我的位置”和地图内的位置提示中。定位失败或拒绝权限时，地图内会显示原因并提供“图上标记”。用户仍可手动停止或重试定位。

楼层图没有地理配准，也没有室内定位设备，因此 GPS **无法得出四楼图上的精确位置**。仅有 GPS 时，地图内显示设备定位状态，不会凭空绘制一个房间位置。手动确认后才显示图上箭头并用于路线起点；重新打开网页时保留的箭头标为“上次手动位置”，不会被当作实时室内定位。

统一位置记录由 `location-model.js` 管理，例如：

```js
{
  type: 'current',
  latitude: 30.1, longitude: 120.2,
  gpsAccuracyMeters: 35, gpsUpdatedAt: 1700000000000,
  floor: '4', x: 40, y: 75,
  indoorSource: 'manual', indoorAccuracyMeters: null,
  indoorUpdatedAt: 1700000000000, updatedAt: 1700000000000
}
```

未知字段用 `null`，而不是虚构坐标。GPS 和室内位置可以独立更新。未来的室内定位服务可调用 `CampusGuide.setIndoorPosition({floor:'4',x,y,accuracyMeters,updatedAt})` 接入当前楼层图，并触发路线重新计算；其他楼层需要先加入对应底图和图数据。位置仅在浏览器本机使用，GPS 经纬度不会写入本地存储或上传服务器。

## 结构与修改原因

| 阶段 | 文件 | 原因 |
| --- | --- | --- |
| 1：架构 | `index.html` | 保留现有静态页面及交互，只增加少量导航接口，避免整体重构。 |
| 2：地图模型 | `navigation-data.js` | 把通道节点、连接和 31 个目标入口与界面分开，便于以后现场校准。 |
| 3：路径算法 | `navigation.js` | 将手动起点吸附到最近的示意通道，按图像像素长度求最短路线。 |
| 4：路线显示 | `navigation-ui.js`、`index.html` | 在楼层图上叠加蓝色 SVG 路线，并接入目标选择、起终点查看和结束导航。 |
| 5：体验 | `index.html` | 手机端固定导航控件，并在页面内说明路线是示意路线。 |
| 自动定位 | `location-model.js`、`index.html` | 页面加载后自动订阅设备定位；统一保存 GPS 与室内图坐标，地图内显示状态、精度和更新时间，失败时保留手动入口。 |

地图坐标均为图片宽高的百分比。房间入口与通道连接依据上传的示意图推断，**未经现场核验**。路线不表示实际距离，也不覆盖跨楼层导航；到达目标时请以现场门牌和可通行路线为准。

## 检查与部署

运行 `node --test tests/*.test.cjs` 检查位置模型、31 个目标的入口、图连通性、路径可达性和最短路径行为。浏览器中还需检查桌面与手机的定位授权、拒绝、搜索、标记、导航、改起点和结束导航。设备定位需要 HTTPS、安全上下文和浏览器授权；某些内置浏览器可能拦截权限请求。

GitHub Pages 从 `main` 分支根目录发布，无构建步骤。新增脚本文件须与 `index.html` 一起发布；手动逐个上传时先上传脚本，最后上传 `index.html`。
